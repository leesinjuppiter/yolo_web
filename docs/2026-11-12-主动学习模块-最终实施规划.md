## 4. 数据、推荐和复核规则

### 4.1 固定数据范围

实施方案将“原训练集”具体定义为：所选注册基线模型来源训练快照中的 train；目标数据集必须对应同一来源数据集，首版类别集合和顺序须与基线一致，不做类别扩充或映射。

- 创建迭代时保存基线模型/权重摘要、原训练输入摘要、固定 val、固定 test（存在时）、类别映射和协议。缺少可用快照/val 时明确阻止，不静默退回 live 数据。
- 未标注候选来自该目标数据集的 train 或未分集范围；已属于 val/test 的图片及固定保护集内容不得进入训练候选。未分集新增图在确认准备训练时明确归入 train，显示变更数量，不重新随机划分。
- 原有 train 修订可从训练图片列表人工选择进入复核，不要求先命中低置信度；其模型预测只是辅助判断，不能因预测与旧标签不符就认定旧标签错误。
- 新上传的补采图使用现有数据集上传入口，返回迭代后手动关联问题参考；上传、关联、选择是不同操作，不能自动完成复核。
- 本轮固定输入 = 原 train 按同图替换已确认修订 + 已确认新增，val/test 沿用冻结集合。未选择或移出队列的原训练图片沿用原快照标签；该行为在预检摘要说明，不能悄悄使用 live 草稿。
- 去重按图片 ID 和原始文件 SHA256；同内容不同文件名不能绕过保护。重新编码、裁剪、近重复和同视频相邻帧不保证被 SHA256 发现，首版不新增相似检索；人工仍需按来源避免场景泄漏。
- 同内容且标签冲突的记录返回可定位冲突，不任取一份；完全相同记录只保留一次并展示排除数。
- test 缺失时允许日常 val 迭代，明确显示“未配置最终测试集”；不能宣称已完成最终验收。test 被历史分析使用过时，也不能把冻结操作解释为恢复了独立性。

### 4.2 推荐策略及阈值方案

下列数值是本规划提出的可调整初始工程默认值，不是经数据实验验证的最优值，也不是额外的用户确认记录。每次任务必须显示并冻结实际值。

| 策略 | 输入要求 | 输出与排序 |
|---|---|---|
| 评估错误优先 | 基线模型在固定 val 上成功完成的逐图诊断 | 仅产生问题参考；按 FN 降序、FP 降序、图片 ID 稳定排序。人工补采/修订另行加入训练候选 |
| 低置信度 | 同类型同类别的基线和目标图片池 | 对保留预测中 confidence 落入区间的图片推荐；按区间内最低 confidence 升序、命中数降序、ID 排序；不称熵或价值评分 |
| 混合推荐 | 上述两路输入齐全 | 同时生成两张独立列表、独立上限；不把错误参考与可训练图片相加成一个训练预算，不加权混合不同量纲 |

推荐初始值：推理保留阈值 0.05，低置信度区间 [0.05, 0.50)，NMS 阈值 0.70；输入尺寸从基线配置预填。要求 `保留阈值 ≤ 区间下限 < 上限 ≤ 1`。S1 的两种上限分别约束问题参考和训练候选，不是自动选中数。上限输入为正整数，候选不足时返回实际数量与原因。

“无预测结果”指经过上述保留阈值和后处理后没有预测，不代表原图没有目标或模型完全漏检。提供单独筛选开关与空分数；在候选上限内先列低置信度命中，再按固定顺序补足无预测待检查图，避免给无预测伪造 confidence=0。用户可单独筛选后人工选择。

同一迭代同一图只出现一个复核条目；多个推荐任务命中时保留所有来源和原因，不重复选中、不覆盖已确认标注。推荐范围在任务提交时冻结，运行期间新增图片留到下一推荐任务处理。

### 4.3 逐图诊断与最终指标区分

- 标准 mAP 继续由 Ultralytics 计算；保存 evaluator 版本、图像尺寸、conf、NMS、max_det、IoU 阈值序列等实际配置。原独立评估使用 conf=0.001，不能把该阈值下的所有 FP 直接解释为实际展示阈值下的误检。
- 日常错误卡片另存诊断协议：建议展示 confidence≥0.25、匹配阈值0.50，均在任务摘要明确；需要不同阈值时生成新的诊断结果，不覆盖旧报告。
- Detect 使用框 IoU，Segment 使用掩膜 IoU并单列框结果，OBB 使用当前 Ultralytics ProbIoU。三类均按类别、一对一匹配；复用已安装匹配规则并保存匹配对索引，不另写一套与指标悄然不同的 TP 算法。
- 匹配 TP 后，未匹配预测为 FP、未匹配 GT 为 FN。类别混淆或低重叠可作为“疑似原因”关联对象展示，不额外增加 FP/FN。无可靠匹配证据不宣称已经区分定位错误和标注错误。
- 每个对象保存原图绝对坐标、类别、confidence、预测/GT 身份和匹配信息；分割保存原始掩膜证据及可编辑轮廓，不用框替代掩膜质量。
- 独立保存总量/按类/逐图结果；指标缺失为 null，不补零。Segment 对比至少包括 Box/Mask mAP50、mAP50-95、Precision、Recall，优先展示 Mask mAP50-95。
- 日常诊断与迭代对比均绑定同一固定 val 和协议；结果只说明此 val 上表现，不能宣称无偏泛化提升。最终 test 由用户另行发起，不回流选样。

### 4.4 草稿、复核与训练资格

采用最少的新机制：复用当前标注保存与 image.version，新增独立复核记录及确认时的标注副本/摘要。首版不另外构建通用标注分支系统。

1. 载入预测仅复制到编辑草稿，并保留模型、推荐任务、原预测对象的关联；不写 reviewed。
2. 保存草稿仍是当前标注保存，可能使数据集状态变 annotated，但本轮训练只认固定清单，不认这个状态即视为已复核。
3. 点击确认时校验图片/类别版本、几何及明确的负样本选择，保存对应标注和复核结果；同一事务完成必要写入。后端不能相信前端传来的 reviewed=true。
4. 原标签、预测、人工编辑为不同图层；预测默认只读。不能将 `source=manual` 当作“未经 AI 辅助”的证据，预测辅助来源记录在复核证据中。
5. Segment 当前只支持单轮廓多边形。载入多分量/孔洞或超点数的预测时显示不能直接转换，允许人工重绘；不悄悄拼接、截断或拟合后当真值。扩展数据格式不属于本轮。
6. 确认无目标时，若有现存对象须先明确删除或确认清空；只有空标注+显式负样本确认可通过，正样本空标签阻止确认。
7. 已复核后任何影响标注/分集/类别语义的更新使对应训练资格失效；非内容变更保守地按当前 version 机制提示重新检查，首版不新建复杂多版本计数系统。
8. 暂时跳过仍为待复核。移出本轮队列保留候选、原图、草稿及历史记录，不能删除数据集图片。选中=0 不视为“全部完成”。
9. 复核页初版锁定类别集合，只允许切换已有类别；需要新增类别应退出本轮并重新建立兼容模型/数据配置。

### 4.5 计数、冻结和多次训练

页面计数由后端提供，基于图像而非目标框数：已选择 = 有效已复核 + 待复核（包括复核过但版本已失效）；有效已复核 = 新增 + 已修订 + 已复核未改动。负样本是这些分组的交叉属性，不再重复加总。

合并后训练总数 = 原训练清单数 + 非重复新增数 − 原清单内确定可去除的完全重复数；修订和未改动均不增加图片数。遇到重复标注冲突则预检失败，此时不显示可提交总数。

S6 的六类检查为：①全队列有效复核；②标注版本/图片/类别摘要一致；③类别、任务及几何兼容；④与固定 val/test 及当前保护分集不重叠；⑤图片唯一性与重复冲突；⑥文件/标签完整性和可训练正样本条件。

预检通过产出只读 manifestId、digest、版本清单和计数。进入训练弹窗只预填，不自动创建任务。统一 training.start 提交时重新核对清单仍有效；变更返回冲突并要求重新预检，不偷偷换用最新数据。worker 按清单物化独立输入，校验实际文件摘要和取消状态，训练运行中不读取 live 标注。

同一迭代可有多个只读清单修订和多个训练尝试，每个尝试绑定一个清单。开始训练后若补充/修订样本，生成新的清单版本，只影响后续尝试。已有运行任务不变。失败保留已复核成果，重新创建尝试即可；注册模型保留现有二次确认。

用户手动指定一个结果模型，系统要求该模型来自本迭代的成功训练并已注册。基线/结果报告均成功且同协议时可完成本轮，提升、持平或退步都允许记录；完成不等于发布或生产合格。完成轮次作为历史只读，后续改善创建下一轮。

### 5.3 通知与生命周期

- 新表复用现有 PostgreSQL change trigger 与 `/api/changes`，通知至少带 topic/table/id/kind；可新增 active_learning、iterations 主题，保持原主题兼容。
- 一张图复核只失效相关候选、队列计数、迭代摘要及待用 manifest，不重载所有模块；采用现有 changeRefresh 合并短时事件。
- SSE 断线期间保留页面已有数据和未保存草稿；恢复 sync 后补取摘要和当前数据。当前编辑图外部版本变化，提示冲突，由用户处理，不覆盖编辑内容。
- KeepAlive 隐藏页面停掉可见页特有订阅和预取；重新激活时消费失效标记再获取。继续提供手动刷新和失败重试。
- worker 队列检查、心跳、SSE keepalive 属于后台运行机制，不等于恢复前端定时全量刷新，不为本任务改造原通知系统。
- 删除保护覆盖迭代基线、结果模型、训练任务与固定证据。必要引用被删时返回原因；不通过级联删除悄悄毁掉迭代历史。首版不额外做批量删除/归档界面。

- [ ] 已有 train 可人工加入修订；补采图手动关联参考；上传不自动选择、更不自动复核。
- [ ] val/test 图片无法直接入队；改名/原字节复制仍被 SHA256 拦截；错误说明指出来源和图像 ID。
- [ ] 保存草稿/载入预测不增加 reviewed；空标注未经明确 negative 确认不能通过。
- [ ] 修改已复核图、分集或类别后有效复核失效；跳过不算完成；选中0张不能准备迭代训练。
- [ ] 预检后修改输入，提交返回冲突；worker 不读取新版 live 标注替代已冻结内容。
- [ ] 10张原训练图 + 2张新增 + 1张修订 + 1张复核未改动，选中4/复核4，最终训练12张；修订仅替换对应图标签。
- [ ] 原训练图片被移出本轮队列后仍使用原快照标注，计数/提示一致；不悄悄丢图或采用草稿。
- [ ] 完全重复、标签冲突、坏文件、类别不兼容均可定位；正常负样本导出空标签而非被误判损坏。
- [ ] 固定 val/test 的文件/标签/类别摘要跨训练尝试保持不变；新训练快照与 manifest 逐项一致。
- [ ] 当前迭代有引用时模型/训练/数据的删除按保护规则处理，不丢失历史证据。

### 9.2 诊断与报告正确性

- [ ] Detect 的完美预测、漏检、误检、错类、重复预测、一对多重叠对象均有预期 TP/FP/FN。
- [ ] Segment 包含“框对但掩膜不对”的用例，Box/Mask结果不同且正确展示；多轮廓/孔洞不能无提示变成一个错误真值。
- [ ] OBB 包含旋转、长细框及角度等价表示；保存的口径明确为 ProbIoU，匹配与所采用评估器一致。
- [ ] 无GT且无预测的已确认负样本、无GT但有预测、存在GT但无预测三种情况分别验证。
- [ ] 同名不同图片不会覆盖逐图统计；证据对象回映射到原图绝对坐标；缩放展示不改坐标。
- [ ] 图卡诊断阈值与标准 mAP 协议分别显示；不能把 conf=0.001 下FP数当成0.25阈值错误数。
- [ ] 同轮比较锁定具体报告 ID；后来创建别的评估不改变旧迭代结论。
- [ ] 不同集合/类别映射/阈值/评估器版本等协议差异显示不可比，缺失不填0；相同比较可显示提升/持平/退步。
- [ ] Segment 展示 Mask 主指标和 Box 辅助指标；test 报告与日常 val 对比分开，完成轮次不等于最终验收通过。

### 9.4 三任务闭环冒烟与回归证据

每种任务各用可控小数据：固定 train/val/test、未标注正图、负图、原训练修订图；另备完全重复、错误类别、文件缺失等故障用例。分别完成“基线 val 诊断 → 三策略检查 → 人工选样/补采关联 → 草稿/确认 → 预检 → CPU 或授权 GPU 小轮训练 → 人工注册 → 固定 val 比较 → 手动指定结果”。至少一次演示失败重试和一次指标退步状态；最终 test 用另一条明确发起的验收操作验证。

回归重点：普通数据集标注/上传/导出、非主动学习训练创建和恢复、模型注册/删除、原 Detect/OBB 独立评估、部署包与验证报告、启动预加载、变化通知/重连、图片缓存。相关现有测试包括 `test_annotation_validation.py`、`test_training_execution.py`、`test_training_api.py`、`test_model_registry.py`、`test_change_notifications.py` 和前端 `changes.test.mjs`、`image-cache.test.mjs`、`forward-cache.test.mjs`、`model-reports.test.mjs`、`preloader.test.mjs`。

交付证据至少记录：Git版本、Conda/Python/Ultralytics/PyTorch版本、执行设备、数据/模型/评估协议/清单摘要、关键任务ID、命令与实际结果、六页截图、请求数量与本地耗时。前端完成类型检查和构建；测试按实际变更范围运行并记录，不把静态检查或一次冒烟称为全部验收。外网传输耗时与服务端计算/前端渲染耗时分开，不用公网延迟单独判产品性能失败。
