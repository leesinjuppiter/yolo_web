# 模型仓库、ONNX 导出与部署包：实现与验证

本轮实现范围：注册模型仓库，Detect/OBB CPU 独立评估，ONNX FP32 导出、配对验证、CPU benchmark，以及部署包生成/下载。保留原版本 vN 和训练来源。已将功能接入开发服务器。远程 SSH 部署属于后续规划。

## 使用方式

开发服务器通过既有 SSH 隧道访问：模型仓库 http://127.0.0.1:15186/#/models ，部署中心 http://127.0.0.1:15186/#/deployments 。此地址需要隧道保持连接。

1. 在成功训练详情登记模型版本，进入模型仓库查看来源。
2. Detect/OBB 模型详情可创建独立评估或 ONNX FP32 导出；选择输入尺寸（32的整数倍）。初版执行设备为 CPU。
3. 部署中心查看导出阶段、日志、原始输出数值检查、精度配对报告及性能条件。
4. 成功导出后点击“生成部署包”；构建完成下载 ZIP。
5. 在匹配的独立 Conda 环境解包，先运行 python -B runtime/verify.py，再按包内 README 安装依赖/运行 runtime/infer.py。
6. 模型归档后禁止新评估、导出、微调和构建；历史记录与已生成包保留。

包内包含 model.onnx、classes.json、输入/预处理配置、manifest、报告、依赖记录、verify.py、infer.py、README、SHA-256 清单。包需要联网安装依赖，不包含离线 wheel；直接依赖固定版本，完整环境记录用于复现参考。验证程序拒绝缺失、额外、越界或被修改的成员。哈希完整性检查不等同数字签名。

## 环境与启动

已有 vision-platform 增装（用户授权）：
- onnx==1.23.2
- onnxruntime==1.31.1
- 由解析器安装 flatbuffers / ml_dtypes / protobuf；PyTorch 保持 2.8.0+cu128，torchvision 保持 0.23.0+cu128。
- 固定依赖入口 backend/requirements-exports.txt。

设置既有 WORKBENCH_DATABASE_URL、WORKBENCH_DATA_DIR 等环境变量；凭据不写入源码。执行：
- python -m alembic upgrade head（新增0010、0011）。
- python -m uvicorn app.main:app --host 127.0.0.1 --port 8000。
- python -m app.training.worker（原训练队列）。
- python -m app.evaluation.worker（CPU评估）。
- python -m app.model_exports.worker（CPU导出与包构建）。

评估和导出执行器各持有独立锁，共享 CPU 模型任务锁，避免二者同时测速；当前未开放 GPU 导出/评估，不将 CPU 结果标为 GPU 性能。用户自有训练/外部负载仍可能影响主机测试，性能报告保留限制说明。

## 验证边界与下一步

这批模型只训练了少量epoch；实测mAP为0，包内样例预测目标数为0。当前验证证明执行和制品链路可运行，不能证明准确率，也未覆盖有正确预测目标时的完整坐标人工复核。生产业务阈值尚未指定，所有包 productionReady=false。

首版评估来自模型来源训练快照的test分集；尚未开放任意独立评估集选择和跨训练任务共享评估快照管理。类和样本、标注、协议一致时才能计算Diff；不适配时显示原因。报告可以下载JSON/CSV，尚未建设服务端对比报告档案库。详情展示与基础评估先行，图片并排可视化、业务推荐、语义版本系列、外部模型导入、PDF、分割/分类导出、TensorRT/INT8等后续按已列边界确认。

SSH目标登记、下发、冷切换、在线运行监控和回滚未在本轮实现。真实目标机系统/架构未指定，当前仅声明开发环境经过验证。既有训练环境克隆能验证隔离前缀中的加载/推理，但离线依赖包、从零安装和不同硬件适配仍需另行验收。
