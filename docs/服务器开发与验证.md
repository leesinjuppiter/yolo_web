## 启动与访问

服务器配置存放于 `/hy-tmp/codex-yolo-20261111/server.env`，权限为 600，包含数据库凭据。不要提交该文件或打印其中的连接串。

```bash
source /usr/local/miniconda3/etc/profile.d/conda.sh
conda activate vision-platform
source /hy-tmp/codex-yolo-20261111/server.env
python -B /hy-tmp/codex-yolo-20261111/start_services.py
```

启动脚本和 PID 记录位于同一个验证目录，已有进程运行时不会重复启动。实例重启后需要先确认 PostgreSQL 17/main 已启动，再启动应用；脚本不是系统服务管理器。

测试日志存在上游 Starlette/httpx、SQLAlchemy 的弃用提示，本轮未为这些无关提示更换依赖或重构代码。

真训练发现并修复的两个问题：

1. Linux runner 的父进程监听线程使用缓冲 stdin 读，正常解释器退出时发生 `_enter_buffered_busy`；改为直接读取文件描述符，并增加 Linux 真实子进程退出回归。
2. PyTorch 2.8 属性返回不带 `GPU-` 的裸 UUID，无法匹配 nvidia-smi；统一标准化普通 UUID，保留 GPU-/MIG- 标识，并用真实 GPU 采样复核。

AMP 测试日志显示上游离线 AMP 自检被跳过，实际训练开启 AMP 且完成；这不等于已完成上游在线自检。

## 返回训练任务时的等待修复

2026-11-11 浏览器复现：详情页点击“返回训练任务”后，旧列表组件已销毁，返回时先出现空白，再经 200 ms 延迟重新请求列表。服务器本机的列表接口三次测得 31/25/27 ms；经当前 SSH 转发的一次请求为 1,354 ms。该测量用于定位网络等待，不是严格性能基准。

前端调整仅涉及 `App.vue` 和 `TrainingView.vue`：

- 使用 Vue KeepAlive 保留列表组件、已有数据、筛选、页码和视图，返回先展示已有内容，并后台刷新。
- 列表重新激活时立即发起刷新；200 ms 防抖只用于筛选变化。
- 列表隐藏时取消请求、停止轮询；重新进入时恢复刷新，避免缓存组件后台持续请求。
